# AI and device status: what is actually real

**Verified 3 Oct 2026 by reading the code (not the documents) and by the tests named below; capabilities A and B and the data-flow sections were rewritten on 4 Oct 2026 for slice V2, capability D, the data-flow section and the local-model facts on 4 Oct 2026 for slice V3, and capability F and the data-flow section on 4 Oct 2026 for slice V4; capability G was rewritten on 5 Oct 2026 for slice V6; D2 (6 Oct 2026) is described in its own section below.** This page says what runs, what needs an external service or credential, what is only exercised by a test double, and what does not exist. It is deliberately conservative: an endpoint existing is not "working". Nothing here is a claim of clinical validity, diagnostic accuracy, regulatory approval or production readiness. The audit with line-level evidence is in [DOCTOR_APP_AUDIT.md](DOCTOR_APP_AUDIT.md); the target architecture is [ADR 0012](adr/0012-local-first-ai-hosted-providers-opt-in.md), the local consultation draft is [ADR 0016](adr/0016-local-ai-consultation-intelligence.md), and Mana AI, the doctor's assistant over the clinic's records, is [ADR 0017](adr/0017-mana-ai-doctor-assistant.md).

## Words used

| Word | Meaning |
| --- | --- |
| **Real** | Runs on this machine with no external service, and is covered by automated tests |
| **Needs a hosted provider** | The code is real but does nothing without a key for an external service **and the server's hosted-AI egress setting turned on** (a key alone enables nothing); then it sends data there, after consent |
| **Test-only** | Exercised only against a test double or a local mock of the external service; never run against the real thing, so its quality with a real model is **unknown** |
| **Simulated** | Stands in for something that does not exist yet, and is labelled so |
| **Unavailable** | Shown to the doctor as "not available" with the reason |
| **Absent** | Does not exist |

## The eight capabilities

| **A. Voice transcription** | **Real, local; measured on synthetic speech only** | **Consent check; browser microphone recording (start, pause, resume, stop) in 20-second parts; transcription by a speech model that runs on this computer** (`services/speech`, `faster-whisper` `small`, CPU, int8, loopback only): each part is transcribed after it is recorded; **timestamps on the recording's own timeline, language per line (with how it was decided), a model score per line (labelled as a model score), the model, runtime and weights SHA-256 on every run**; audio upload and storage; typed or pasted transcript. **No hosted speech provider exists in the code** and there is no fallback: without the local service the screen says "Local transcription unavailable". **No model identifies speakers**: the doctor assigns them, line by line (append-only review). | **C. Patient-context retrieval** | **Real** | The history read model (`GET /api/patients/:id/history`: allergies, conditions, medicines, results, signed consultations, latest vitals), the context assembly for recommendations, and Mana's record reader are deterministic, facility-scoped and audited. All data is typed in by staff or comes from signed consultations (there is no laboratory or pharmacy feed). There is no vector or semantic retrieval | No | API and database tests; e2e |
| **D. AI summary: the consultation draft** | **Real, local; measured on 12 synthetic cases only; slow** | **A language model that runs on this computer** (`llama.cpp` b11379 with `Qwen3.5-4B` Q4_K_M, `127.0.0.1:8081`, CPU, a per-install secret, no network) reads the **authorised** record, the doctor's own notes for the visit, the vital signs and **only the points the doctor confirmed**, and writes a structured **AI DRAFT**: summary, presenting problem, symptoms, observations, relevant history, allergies, medicines, **potential considerations, investigations and medication considerations** (never orders or doses), **missing information** and **uncertainties**. Each statement cites the record items it rests on; **the server, not the model, decides its support state** (*supported by record, inferred, not found, conflicting, outdated*) and removes or marks what it cannot verify (an unknown figure, a made-up medicine, a dose, a missing citation, a reversed "no", an absence the record contradicts). Conflicts are found by **fixed rules**, not by the model. The doctor accepts, edits or rejects each statement; **nothing reaches the note, the diagnoses or the prescription without a separate "Add to note"**. A draft takes **minutes** on this CPU, can be cancelled, is versioned, audited and marked **STALE** when the record changes. Without the model the screen says **"Local AI unavailable."**; there is no placeholder output and **no fallback to a hosted model**. Needs a one-time, owner-approved download (about 2.74 GB model, 19 MB runtime; `npm run llm:setup`). The **patient summary** on the consultation screen is still composed from the record by fixed rules and labelled "not AI-generated". The older per-section note drafts and Mana's optional summary are separate, hosted and off unless egress is allowed | No (local). `ANTHROPIC_API_KEY` **and hosted egress on** only for the older hosted steps | 130 new API tests, none of which calls a model or provider (the pipeline against a stand-in model 39, the checks against answers that invent or obey an injected instruction 50, the inputs 6, the scoring of the evaluation 11, the local client against a loopback stand-in 12, the launcher and lock files 12), in the browser against a labelled stand-in server (`e2e/consult.spec.ts`), and **the real model on 12 synthetic cases** ([safety/AI_MODELS.md](safety/AI_MODELS.md)), plus an opt-in browser run against the real model (`e2e/consult-real.spec.ts`); **no real consultation, no real clinician review, no clinical validation** |
| **E. AI recommendations** | **Rules are real; the AI part needs a hosted provider and is test-only** | `safety-rules-v1` always runs and needs no provider (allergy and record conflicts, vital-sign and red-flag checks): **real**. An optional language-model step adds suggestions. The AI is contractually barred from drafting diagnoses or prescriptions | `ANTHROPIC_API_KEY` **and hosted egress on** for the AI step | Rules: unit and API tests. AI step: **test-only** |
| **F. Mana AI** | **Real, local, read-only; measured on synthetic cases only; slow** | A **doctor-facing assistant over the clinic's own records** (V4, [ADR 0017](adr/0017-mana-ai-doctor-assistant.md)). Per question: the **local model plans** what to look up (it sees the doctor's words and patient *handles*, never a record; a name the doctor typed reaches it as typed), the **server runs only registered, read-only tools** after checking the doctor's permissions, scoped to the doctor's clinic, with the patient's consent to AI help checked (ten tools: a patient's record by topic, visits, a signed consultation, finding a patient, today's queue, recent check-ins, appointments, the doctor's own consultations, the clinic, the current context), the **local model writes the answer from what the tools returned** (patients as handles; a patient's own name, MRN and telephone number, and any telephone or record number, replaced in free text by patterns), and **code checks every statement against the facts it cites** and removes what it cannot tie to them; **every answer about a patient starts with "About <name> · MRN · age and sex", written by the server**. Conflicts, old records and what is not recorded are **found by the fixed rules and shown whatever the model wrote**. A name that fits several patients is asked about, never guessed; a question that names another patient than the plan is about is stopped before anything is read (the plan must be about a patient whose name has **every** word the doctor wrote: Rahul Sharma is not Rahul Verma); a plan that does not fit the question is sent back to the planner once. It **cannot prescribe, sign, change or delete anything** (no tool writes; a request to is refused in fixed words), answers **no general medical question** (no governed source exists), and says **"Mana is currently unavailable."** when the model is not running (nothing is stored, nothing is made up, no hosted fallback). Conversations, tool calls and the records an answer rests on are stored append-only; the audit log holds ids and counts, never question or answer text, and **what a question read is written to it in one transaction with the tool rows: if it cannot be written, the question fails and nothing is shown**. The slice-1 rules answers and optional hosted summary **remain as an API but have no screen**. **Absent:** any tool that writes, chaining (a lookup that depends on another's result), clinical search across all patients, streaming, general medical knowledge, other languages, a retention schedule, clinical validation | **No** (the local model needs the per-install secret, which never reaches a browser). A hosted model is possible only behind the egress policy and a key, and has never been run | API tests with a stand-in model (164 tests, and the whole suite passes), end-to-end tests with a stand-in model server, and a **synthetic evaluation through the real local model** (49 cases, 55 questions, 54 of 55 ended as they should, one correct answer removed by a conservative check; [safety/AI_MODELS.md](safety/AI_MODELS.md) §10); the hosted path and the slice-1 summary are **test-only** |
| **G. Thermal analysis** | **Real measurement; no model; a summary composed by fixed rules, not AI; no camera integrated** | FLIR radiometric images are decoded to a temperature matrix (`flyr`); the whole image gives min, max, mean and (since V6) standard deviation; regions (rectangle, ellipse and, since V6, polygon) give statistics and paired differences, with pixels without a reading left out; fixed-threshold "experimental flags" (`rules-v1`: an area at least 2 SD above the image mean over 12 pixels or more; an asymmetry at a mean difference of 1.0 °C or more), always marked not validated. **No trained model exists**: `GET /api/thermal/model-status` says "No trained thermal model is installed." and the screen shows MODEL UNAVAILABLE; the evaluation pipeline's baseline (`thermal-eval-v1`) is a measurement of a dataset, not a model. There is no image-quality or confidence output, and **no pain analysis or pain score**. **The thermal summary (V6, `thermal-summary-v1`) is composed by fixed rules from the stored measurements and the rules' output, not by AI** (no language model): each statement says whether it is measured, an experimental rule, the model statement ("No trained thermal model is installed: no model finding.") or a limitation (skin-surface temperature only; it does not measure pain and does not show swelling, inflammation, infection or fractures; not clinically validated). The doctor accepts, edits or rejects it once; only an accepted or edited summary of the same consultation, not simulated, reaches the note, by a separate *Add to Examination* (where the note's provenance line calls it "AI-assisted text", the note's wording for every insertion: a known limitation). **How images arrive:** uploaded or imported radiometric files; **live capture from a FLIR ONE through a native Android bridge that is written but not compiled and not run** ([THERMAL_CAMERA.md](THERMAL_CAMERA.md)); a **simulator** (`thermal-sim-v1`) whose captures are stored and shown as SIMULATED and given to no model, assistant, patient portal, dataset export or note. Mana and the consultation draft read approved, non-simulated measurements and the doctor-reviewed summary (`mana-record-v3`). [ADR 0020](adr/0020-v6-thermal-capture-in-the-consultation.md) | No (a local Python service). The bridge would need the FLIR SDK, which needs a free FLIR developer account and acceptance of FLIR's licence (not done) | pytest of the thermal service (decoding, standard deviation, regions including polygons, pixels without a reading, the rules, the model status), API tests (`thermal-v6.test.ts`: sources, NON-RADIOMETRIC, the simulator, polygons, the model status; `thermal-summary.test.ts`: the composer, the single decision, the note, what Mana and the draft read; and the earlier thermal tests), web unit tests (`thermal.test.ts`, `thermalCamera.test.ts`, the latter against a stand-in bridge object) and an end-to-end test (`e2e/thermal-v6.spec.ts`) on a public sample image and simulated captures. **Never run with a camera; the bridge has never been compiled** |
| **H. Device readings** | **Boundary real, with reading states and a labelled simulator; no hardware** | A token-authenticated gateway stores readings as *device, unverified*, once per batch, and only the kinds a device may send (**never blood pressure**, which staff enter). Every device value has a **state** decided on the server's clock (live, stale, disconnected, no data, unavailable) and is shown in the consultation on a "Device readings" card that is re-read every 5 seconds. **No device or gateway program exists.** A **simulator** (a program that generates values, `npm run devices:simulate`) exercises the boundary: what it sends is stored and shown as **SIMULATED**, is in no visit's vital signs, is never shown to the patient and is **never given to a model or the record rules**. Where staff and a device both supplied a value, the staff measurement stands. The consultation draft and Mana read device readings labelled "device reading (device unverified)". [ADR 0018](adr/0018-device-readings-states-gateway-and-simulator.md) | No | API tests (44 in `devices-v5.test.ts`), web unit tests, e2e in a real browser with the test posting as a gateway. **Never run with a device** |
| *Stethoscope* | **Recording, upload and playback; no stethoscope tested; no analysis** | A file uploaded by staff, a recording made **in the browser** from an audio input the member of staff chooses (the system cannot tell what an input is, and says so), or a recording sent by a gateway with a stethoscope record's token. Files are checked by content. A simulator's "recording" is generated tones, marked SIMULATED AUDIO | No | API and e2e (Chromium's synthetic audio input; generated tones) |

## What leaves this machine, and when

- With **nothing configured, nothing is sent.** The test configuration never carries provider keys, and tests never call a real provider.
- **Consultation audio never leaves this computer, by default.** Speech-to-text is local only: the hosted adapter was removed, `AI_STT_API_KEY` is ignored (with a start-up warning), the speech URL must be loopback unless the clinic sets `SPEECH_ALLOW_NON_LOOPBACK=true` on purpose to use its own speech service on another computer (the screens then name that host and say that audio goes there; it is never a hosted AI provider), redirects are refused, and a down service means "Local transcription unavailable", never a fallback. Important points are found by local rules.
- **Transcript *text* leaves this machine only if hosted AI egress is allowed on purpose, and it is OFF by default (V2.1, [ADR 0015](adr/0015-hosted-ai-egress-policy-and-speech-service-hardening.md)).** `ai.egress.hostedProviders` in `config/adaxai.yaml` (false) or `AI_EGRESS_HOSTED` (true/false) decides; **a provider key in `.env` enables nothing by itself**, so on this development machine, which holds an Anthropic key, drafting, AI recommendations, Mana summaries and photo descriptions are **unavailable until egress is turned on**. With it on, "Generate draft", AI suggestions, Mana summaries and photo description send consultation text (the patient's registered name, MRN and phone number replaced; best effort) to Anthropic **after the patient's consent, when the doctor clicks**, and the screens say so and where. The old hosted speech key in `.env` (`AI_STT_API_KEY`) is ignored. Tested with a request-counting stand-in: key present + egress off = zero requests.
- Each use is gated by a recorded consent (`ai_recording`, `ai_record_assistant`, `ai_image_analysis`) and audited with the model, prompt version and input and output hashes.
- **Mana AI questions (V4) go only to the same language model on this computer, in two calls.** The planner receives the doctor's own words (a name the doctor typed is in them), the date, and patient *handles*; the writer receives the question and short statements the tools made from records, with patients as handles, never a name, MRN or telephone number *from a record*. With the model not running the answer is "Mana is currently unavailable." and the question is not stored. A hosted model for Mana is possible only under the same egress policy and a key, then needs the patient's consent to be *granted*, and has never been run.
- **Consultation drafts (V3) go only to a language model on this computer** (`http://127.0.0.1:8081`, llama.cpp; the client refuses any other address unless an operator allows it on purpose, refuses redirects, and sends a per-install secret that never reaches a browser). With the model not running the screen says "Local AI unavailable." and nothing is made; **a down local model is never replaced by a hosted one**. A hosted reasoning mode exists in the code (`ai.reasoning.provider: hosted`) only behind the egress policy and a key; it has never been run against the real service. Tested with a request-counting stand-in: local mode and a key present + egress off = zero requests to any hosted address.
- **Built (ADR 0014, ADR 0015, ADR 0016):** the local speech boundary, the local extractor, "a key alone enables nothing" for the hosted language-model steps (an explicit server setting, off by default), and **the local chat model with its provider abstraction** (consultation drafts). **Still planned (ADR 0012, not built):** moving the older hosted steps (note drafts, recommendations, Mana summaries, image descriptions) onto the same abstraction. This machine has an RTX 2050 (4 GB), 15.7 GB of RAM; the speech model and the language model run on the CPU.

## Raw, extracted and confirmed

| Stage | Where | Rule |
| --- | --- | --- |
| **Raw transcript** | `transcript_segments` (+ `transcript_chunks`, `transcript_segment_speakers`) | Append-only; text exactly as heard, never translated; times, language, model score and run on each line; the speaker is **never** set by the model: it comes from a typed "Doctor:" / "Patient:" prefix (typed text) or from the doctor's assignment (append-only review) |
| **Extracted draft** | `clinical_facts` (important points), `ai_draft_items`, recommendations | Always *pending*, always marked as extracted/AI with the rules or model version and whether it ran locally, never part of the record; a fact is carried forward when the doctor re-runs extraction (confirmed ones are not duplicated, rejected ones do not return) |
| **Doctor-confirmed** | accepted or edited item (shown as *Doctor confirmed*), then a recorded insertion into the note | Confirming does **not** write to the note: only `POST /encounters/:id/insertions` ("Add to note"), with provenance; flagged items need an explicit confirmation; **nothing AI-produced is signed or inserted without the doctor**. `listConfirmedPoints` is the only read the later summary will use |

Accepting a *note-draft* item does not insert it: as with the important points and the consultation-draft statements, the doctor accepts or edits it and then adds it with a separate "Add to <section>", which the server records with a reference to the suggestion. The doctor still signs.

## What the final Doctor HERO changed here ([ADR 0023](adr/0023-doctor-hero-final-application.md))

- **No new model, no new prompt, no hosted AI.** The local model (Qwen3.5-4B via llama.cpp) and the local speech model (faster-whisper `small`) are the same; the draft is now reached through **Generate prescription** and reviewed on the prescription page. AI never creates a prescription row.
- **Voice transcription (A):** recording now starts with a new consultation when the patient's recording consent is on record (never otherwise; never the synthetic demo; never on a reload), in 10-second parts. **Important-point extraction (B)** runs by itself after each part (the same fixed rules, local only); unchanged pending points keep their id; nothing is confirmed except by the doctor. No model identifies speakers.
- **Mana (F):** a floating control on every doctor page. **Fixed-rule answers without the model** for next patient, patients seen today, a patient's arrival time, who has waited longest, the nurse's triage (reason, priority, staff vitals, the triage note), orders and lab status (always "SIMULATED lab": no laboratory is connected) and a document's typed report text — labelled "From the records (fixed rules)", answered even while the model is busy or down. **Voice questions**: a clip of at most 30 s is transcribed in memory by the local speech model and never stored (in a consultation it needs the patient's recording consent); **spoken answers** use only voices that run on this computer (`localService`), off by default. **Actions**: only from the doctor's own fully specified words in their own open consultation; Mana proposes, the doctor approves, the page adds the row as the doctor's act; the server never writes the prescription.
- **Service orders:** the only provider is a deterministic **simulated laboratory**; a completed simulated order says "no test was performed and no result values exist". Not AI, not a laboratory.
- **The digital pen:** handwriting is stored as strokes; **there is no handwriting recognition** and Mana and the draft never read it.
- **Thermal (G):** unchanged in what it computes (measurements, ROI statistics, fixed rules; MODEL UNAVAILABLE); the doctor's Thermal page shows measurements only.

## What Doctor HERO (Step 3) changed here

- **No new model, no new prompt.** The consultation draft (D) now reports the local model's **real token count while it writes** (the client streams only to count; the assembled answer was checked byte for byte against the whole answer from the real server) and records **what was sent** (`inputsUsed`). Measured on this machine's GPU (llama.cpp b11379 CUDA, Qwen3.5-4B Q4_K_M) on the synthetic demo child: **36.0 s on the server, 37.7 s from the click**, about 44 tokens/s; earlier runs 29–43 s. The 10-second target is **not met**.
- **Voice transcription (A):** a **synthetic demo consultation** (eight WAV files of two Windows computer voices) can be played through the real local speech model (`faster-whisper` `small`) as live parts; the transcript stores `audio_origin = demo_synthetic` and is shown, to the overview and to Mana, as **synthetic demo audio, not a real consultation**. Measured on the development stack: the 8 parts heard word for word (9 lines), the last line about 40 s after Play (30 s of audio). No model assigns speakers.
- **Checks:** `consult-checks-v3` removes "no known allergies" when the record has no allergy status; Mana's medicines answer starts with the recorded medicine list (`mana-record-v4`, `mana-tools-v4`); Mana's statements resting on synthetic demo audio must say so (`mana-answer-checks-v5`).
- **Stethoscope:** a waveform of each recording is drawn in the browser from its amplitude, captioned "Amplitude of the recording. Not an analysis."; recordings are still not analysed by any model.

## What D2 changed here

- **No new AI.** D2 adds no model, no prompt and no new kind of AI output. The consultation's context (`GET /api/encounters/:id/context`) and its **summary (`multimodal-summary-v2`) are composed by fixed rules**, and its disagreements are found by fixed rules (`context-conflicts-v2`); both are advisory and never written to the note or the record. [ADR 0021](adr/0021-d2-multimodal-consultation-context.md).
- **Mana (capability F)** has one more read-only tool, `consultation_context` (`mana-tools-v3`), and four suggested consultation questions with fixed plans (no planner call); the planner prompt is unchanged (`mana-assistant-plan-v2`), so a free-text question is rarely routed to the tool. Nothing simulated is given to the model; consent to thermal imaging and to recording and AI assistance are applied to what it is given. The answer checks (`mana-answer-checks-v4`) hold every statement to its fact's trust (a device reading said to be unverified, a recording not analysed, an extracted point to review) and let nothing be added to a recording, a thermal measurement or a simulator's output. Asked of the real local model on the development stack, it answered in 5 to 7 seconds; its checks removed one or two statements of each answer (safe, terse). Tests: `mana-tools`, `mana-assistant` (with a labelled stand-in model), `mana-answer`.
- **V3 (capability D)** is unchanged: its inputs are as before D2 (a stethoscope recording given to it was removed after the review: its checks would have let an invented sound through).

## What slice V6 changed here

It added **no model and no AI**. Thermal imaging moved into the consultation (capability G, [ADR 0020](adr/0020-v6-thermal-capture-in-the-consultation.md)): a workspace that captures through a FLIR ONE bridge that has **not been compiled or run**, imports earlier radiometric files, and measures them as before. The new **thermal summary is composed by fixed rules**, labelled statement by statement, and reviewed by the doctor before a separate *Add to Examination*; the model status says that no trained thermal model is installed, and nothing on the screen comes from one. Simulated thermal captures are kept out of the patient portal, the older assistant's context, the record Mana and the consultation draft read (`mana-record-v3`), dataset exports and notes. It did **not** add a thermal model, pain analysis, an image-quality score, a working camera or any clinical validation.

## What slice V4 changed here

It made capability F a conversation: **Mana AI**, a read-only assistant that plans with the local model, reads only what the doctor may see through ten registered tools, writes from what they returned and is checked by code (ADR 0017). The screen's old Mana panel (rules answers about one patient, an optional hosted summary, "insert into the note") was **replaced** by the new panel; the slice-1 API and stored answers remain without a screen. It added no tool that writes, no route that takes a tool or a patient from the client, no insertion into the note, and no fallback to a hosted model. It did **not** add chaining, general medical knowledge, a retention rule, a hosted run, or any clinical validation.

## What slice V3 changed here

It made the **consultation draft** (capability D) real and local: a pinned open-weight model on this computer, a provider abstraction (`local` / `hosted` behind egress / `none`, no fallback), authorisation and consent checked before any record is read for the model, a strict structured output, server-side verification of every statement, support states and conflict rules decided by code, doctor review with nothing written without a separate act, versioning, audit, stale marking and cancellation (ADR 0016). It measured the model on 12 synthetic cases ([safety/AI_MODELS.md](safety/AI_MODELS.md)). It did **not** build Mana on the local model (V4), speaker identification, other languages, device or thermal models, or any clinical validation. **What it cannot do:** recognise a wrong statement that is worded plausibly and cites a real record item; it is a draft because of that.

## What slice V2.1 changed here

It closed the hosted-egress gap: hosted AI is now an explicit server setting that is off by default, with no change to what the AI steps do when it is on. It also hardened the speech service (content checks, bounds, limits), made live recordings end in the withdrawal step itself, and added the plain statements of what is stored and what withdrawal does not delete ([safety/CAPTURE_DATA.md](safety/CAPTURE_DATA.md)). No capability was added.

## What slice V2 changed here

It made capability A real and local and capability B local and rule-based, added the raw / extracted / confirmed separation to the consultation screen, and removed the hosted speech path. It did **not** build the consultation summary (D), full Mana (F), device or thermal models, or any language-model change; drafting, recommendations and image description are as before (keyed, external, after consent) except that the screen now discloses that text goes to an external service. Everything above was verified against the code and the tests named in [STATUS.md](STATUS.md) on 4 Oct 2026; nothing here is clinical validation.

### Earlier (slice V1)

Nothing in the AI itself: it added the deterministic patient context (C) and the patient summary, and removed no safeguard.
