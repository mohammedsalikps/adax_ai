# Datasets and their provenance

**Status: started 3 Oct 2026, updated 4 Oct 2026 (slices V2 and V3).** One entry per dataset used in development, demonstration or testing. Nothing in this repository comes from a real patient, and **no external dataset is used**: before one is, its licence, permitted use, source, preprocessing and de-identification must be verified and written here.

## Synthetic hospital dataset v1 (`npm run demo:hospital`)

| | |
| --- | --- |
| What | 12 fictional patients across general medicine, paediatrics and orthopaedics, 2 extra staff accounts (an orthopaedics doctor, a paediatrics nurse), and for each patient allergies, conditions, medicines (one stopped), investigation results, earlier signed consultations (1 to 3, with vitals, notes, diagnoses and prescriptions) and today's activity (appointments, a queue in every state) |
| Origin | Written by hand for this project in `apps/api/src/db/hospital-seed-data.ts`. Names, dates, values and histories are invented. No real person, no copied record, no scraped or downloaded data, no model-generated text |
| Marking | Every history entry and every patient made by it carries `data_origin = synthetic`; the staff names and the facility say "(synthetic)"; the product shows a "synthetic data only" banner and a "Synthetic" tag on the patient. The seed **refuses to run** unless all of these hold: the deployment is not production, its `DATA_ORIGIN` is `synthetic`, the facility name ends in "(synthetic)", and no patient in the database is marked `clinical`. Its patients' telephone numbers are from a range no mobile operator issues (they start with 5), so no message could reach a real person |
| Dates | Relative to the day it runs (histories always look recent). Earlier consultations are signed with a historical date by holding the clock the API reads for the one signing request; they verify as untouched. The audit log shows the day the seed ran |
| Medical content | Ordinary, conservative examples (for example metformin 500 mg twice daily, HbA1c 7.2 %, an iron-deficiency picture with a low ferritin). **It is not clinical guidance, not a validated case set, and was not reviewed by a clinician.** A test checks that no medicine in a patient's history is one that patient is recorded as allergic to, **by name and by drug class** (for example a penicillin allergy also excludes amoxicillin) |
| Use | Demonstration, interface testing and the automated tests of the history model. **Not a training set and not an evaluation set**: 12 hand-written patients are far too few and too uniform to say anything about a model's performance |
| Splits, metrics, failure cases | Not applicable (no model is trained or evaluated on it). The AI evaluation set built in slice V2 is a separate dataset with its own entry below |
| Gaps against the target list | Not yet in the dataset: device readings, thermal studies, stethoscope recordings, transcripts, AI outputs, a portal account for any patient, more than one facility |
| Re-running | Idempotent and resumable: a patient is recognised by **full name and date of birth** (not by phone number) and is never made twice; each step of a patient's history (consent, allergy, condition, medicine, result, earlier consultation) is done only if it is not already there, so a run that stopped half way is completed by the next one; today's activity is added once per day. Dates and times are changed directly in the database only inside one transaction with the trigger-skipping setting scoped to it |

## Synthetic consultation set v1 (`data/eval/consultations-v1`), with its synthetic speech (slice V2)

| | |
| --- | --- |
| What | **15 scripted, fictional doctor-patient consultations** (General Medicine outpatient): 12 in English (c01 to c12, 24 to 26 turns each), 2 in Hindi (Devanagari, h01, h02) and 1 in Hinglish (Roman script, x01), with **hand-labelled "gold" important points** (406 rows; categories: chief complaint, symptoms, durations, patient concerns, history, allergies, medicines, investigations, examination, assessment, plan, follow-up, vital signs, red flags), including negated, hedged, irrelevant (small talk, questions, hypotheticals) and ambiguous statements |
| Origin | Written by an AI assistant (Claude) on 3 Oct 2026 as fictional dialogue; the gold labels were assigned by the same author in one pass. **No real patient, clinic, person, recording or record is described, copied or derived; no external dataset is used.** Names are invented first names; there are no real phone numbers or identifiers |
| Marking | Every file has `"synthetic": true` (checked by `validate.mjs` and by the loader) and says so in its README. The files are test data only and are never loaded into a patient record |
| Medical content | Ordinary and illustrative; **not reviewed by a clinician, not clinical guidance, not a validated case set** |
| Use | **Evaluation and regression tests of the important-point rules and of the speech pipeline only.** Not a training set (the rules are hand-written and nothing is trained), not a validation set for any clinical claim |
| Splits | `dev` c01 to c08 (used while writing the rules: tuning against it is expected); `test` c09 to c12, h01, h02, x01 (held out; run **once** after the rules were frozen). A change tuned on `test` turns it into a development split and must be recorded here and in [AI_MODELS.md](AI_MODELS.md) |
| Speech audio | The English files are read aloud by the three **offline Windows text-to-speech voices** on this computer (`synthesise-audio.ps1`: David en-US for the doctor, Zira en-US and Hazel en-GB for the patient). The audio (about 64 MB, 302 WAV files) is generated locally, **git-ignored** (`data/eval/audio/`) and never leaves the machine. It is clean, quiet, one voice at a time: **not representative of clinic audio**. No Hindi or Hinglish audio exists (no voice for those languages is installed, and installing one is a download that was not approved) |
| Metrics | Per-category precision, recall and F1 of the important points (one-to-one matching on category, turn and key phrase), negation and hedge agreement, who-said-it agreement; word error rate with a documented normalisation, language identification, speed and segment-time error of the speech model. Results: [`data/eval/results/extraction-v1.md`](../../data/eval/results/extraction-v1.md), [`data/eval/results/stt-v1.md`](../../data/eval/results/stt-v1.md), summarised and caveated in [AI_MODELS.md](AI_MODELS.md) |
| Known failure cases | Held-out recall is much lower than development recall (53 % against 89 %): the rule lists do not know phrasings they were not written for. Assessments, examination findings, past history and symptoms are missed most; durations are weak (precision 17 %, recall 20 % on the test split); all red-flag rows were missed (1 on dev, 3 on test). Hindi and Hinglish: nothing is extracted (intended) |
| Limits | Small (a difference of a few points is noise); one author and one annotator, no inter-annotator agreement; scripted text is tidier than speech; one specialty and setting; synthetic voices only; no accents, noise, overlap, children or long recordings |
| Gaps against the target list | Real recorded consultations (none exist here), Tamil, Hindi audio, code-mixed audio, a second annotator, a clinician review of the labels |

## Synthetic consultation-draft cases v1 (`data/eval/consult-v1/cases.json`) (slice V3)

| | |
| --- | --- |
| What | **12 fictional cases** (c01 to c12), each holding what the consultation-draft step is given for one visit (**78 record items in all**, with the ids the model cites: this visit's reason and draft note, vital signs, allergies, history, an earlier signed note, results, confirmed points), **what the fixed rules found** for it (conflicts, old items, what is not recorded), and **what a careful reader would expect of a draft**: facts it should cover (each with the words that count as covering it and the record items it should cite), words and patterns that must **never** appear in what is kept (a diagnosis stated as a fact, a dose, an invented allergy, an obeyed instruction, the system prompt), what is plainly missing, and whether the rules' conflict must be marked |
| Coverage of situations | A conflict between a recorded allergy and a drafted medicine (c01); old results and an old consultation (c02); a sparse record with no allergy status (c03); a child with no weight (c04); a visit with a reason and nothing else, where the model must not invent (c05); two disagreeing blood pressure readings (c06); "no known allergies" beside a listed allergy (c07); **an instruction addressed to an AI hidden in an earlier signed note** (c08); two inhalers (c09); a stopped medicine and a slow heart rate (c10); a long record of which only the newest items fit the budget (c11); a confirmed point written in Hindi and English, a probe of the English-only limit (c12) |
| Origin | Written by an AI assistant (Claude) on 4 Oct 2026 as fictional patients and records. **No real patient, clinic, record or person is described, copied or derived; no external dataset is used.** The expectations were assigned by the same author who wrote the checks |
| Marking | The file says it is synthetic (its `note`), the report repeats it, and the cases are test data only: **they are never loaded into a patient record**. A unit test checks the file's structure (unique ids and refs, every expected ref exists, every pattern compiles) and that the scoring catches a leaked dose, a missed fact and an uncited fact |
| Medical content | Ordinary and illustrative, written to exercise the checks; **not reviewed by a clinician, not clinical guidance, not a validated case set** |
| Use | **Evaluation of the consultation-draft step with the real local model, and regression tests of the scoring.** Not a training set (nothing is trained or fine-tuned), not a validation set for any clinical claim |
| Splits | `dev` c01, c02, c03, c06, c08 (looked at while the prompt and the checks were written: tuning against them is expected); `test` c04, c05, c07, c09, c10, c11, c12 (not run against the model until the prompt (`consult-draft-v1`, SHA-256 `c602e4a6…`) was frozen). **A change made after seeing a test result turns that case into a development case and must be recorded here and in [AI_MODELS.md](AI_MODELS.md).** The development cases were used to tune the prompt (three rewordings, each followed by a run of all five) and the checks. **What happened to the test split, in order:** (1) *First recording* (3 Oct 2026, 22:56 to 23:34 UTC): every case run once against a development server with the runtime's default prompt caching on, after it had answered many other prompts. (2) *After reading those outputs, three things changed, none of them the prompt:* c11's summary came back cut in the middle of a word at the answer schema's 360-character limit, so the limits were raised and a statement is now cut by the checks at a sentence or a word (c11 was re-run; c01, c05 and c12 were re-run too and came back identical, which showed that the change touches only a string that reached the old limit); diagnosis codes in brackets that the record carries ("(E11)", "(J44)") were removed from statements as if they were citations (seen in c02, c09, c10 and c11); and the evaluation also counts what the fixed rules' record check says is not recorded and counts figures written in words the way the checks do. (3) *An independent review of the checks* (the reviewer was told not to open the results) led to many changes in them: a reversed "no" in either direction, the model's own label no longer switching rules off, characters and digits that hid words, the AI's reasons held to the suggestions' rules, an absence that an item the statement cites contradicts, and more ([STATUS.md](../STATUS.md)). They were made without looking at the results, but the checks the test cases are scored by are no longer the ones they were first scored by. (4) *The first recording was found to depend on the server's history* (the same three cases run again on freshly started servers all came back different, and none of the twelve answers of the second recording equals the first's: [AI_MODELS.md](AI_MODELS.md) §9.2), so the server's settings were changed to the shipped ones (prompt caching off) and **all twelve cases were run again (second recording, 4 Oct 2026, 00:44 to 01:13 UTC)**: that is the record reported. The first recording is kept as `data/eval/results/consult-v1.superseded.raw.json` and is not scored in any report. (5) *After reading the second recording* one check was added (an absence claimed inside a sentence of a summary, and an already-cited item that contradicts an absence now counts), because c06's summary carried a false absence sentence (c06 is a development case); the recorded answers were re-scored, not re-asked. **So the second record's answers were not seen when the checks were written, but the checks were shaped by the first record's answers and by a review, and the label "held out" means no more than that the prompt was frozen before these cases were first run** |
| Metrics | Whether the answer came back in the required form; statements written, kept and removed by the checks, by reason; expected facts covered by a kept statement and whether it cited one of the items that state it; missing information named; conflicts the rules found that the draft marked "conflicting"; **forbidden content found in what was kept**; what the checks had to catch in the model's own answers; time per draft; and, on a subset, how alike two runs of the same case are. **No percentage of "accuracy" is computed or claimed.** Results: [`data/eval/results/consult-v1.md`](../../data/eval/results/consult-v1.md), summarised and caveated in [AI_MODELS.md](AI_MODELS.md) |
| Limits | Small (a difference of one or two cases is noise); one author who also wrote the checks, so the cases probe what the author thought of; no second reader, no clinician; English; short records; one model; one machine; the model is run at temperature 0 on one prompt |
| Gaps against the target list | Real or realistic de-identified records (none exist here), cases written by a clinician, other languages, long free-text notes, children's dosing scenarios, multi-morbidity, a second model for comparison |

## Synthetic Mana AI evaluation v1 (`data/eval/mana-v1/cases.json`, over `apps/api/src/eval/mana-fixture.ts`) (slice V4)

| | |
| --- | --- |
| What | **49 fictional cases (55 questions)** a doctor could ask Mana, over **one synthetic clinic world** built through the real API by `mana-fixture.ts`: **two clinics** (the second shares first names with the first), **thirteen invented patients** (eleven in the first clinic, two in the second) with allergies, conditions, medicines, an investigation result, signed consultations (some moved back in time with the database's own superuser, as the tests do), **two signed notes that carry an instruction to an AI (one in the usual words, one paraphrased) and one that carries identifiers in its text (the patient's own name, record number and telephone number, a relative's number, another record number)**, **today's queue in every state**, **appointments tomorrow**, a doctor in each department, a nurse and an administrator. Each question says what a correct, authorised, grounded answer must contain (the tool and arguments the plan should choose, patterns that must be in what the doctor can open, patterns that must be in the statements, the patient it must be about) and what it must **never** contain (another patient's record, another clinic's, an obeyed instruction, a link or telephone number), the findings the rules must show, the notice (read-only, no knowledge source, beyond a doctor's work, choose a patient) and the outcome |
| Coverage of situations | The patient of the open consultation (briefing, allergies); a named patient (allergies, medicines, last prescription, diagnoses, vital signs compared, investigations, visits, the last signed consultation, a word search); the clinic's day (who is waiting, my queue, my appointments tomorrow, who checked in about two hours ago, my consultations today, the departments); finding a patient; **a record that says "no known allergies" and lists an allergy** (conflict); **nothing recorded about allergies** (must not become "no allergies"); **a prescription more than a year old** (outdated); **a patient who is not in the clinic**; **two patients called Rahul** (the doctor must choose, twice); **the other clinic's patient by name and by MRN**, the other clinic's own queue and own patient, a nurse asking (refused); **requests to prescribe, sign, add to a record, cancel an appointment** (refused, nothing changes); a general medical question; every patient's allergies; the audit log; **a question that tells Mana to ignore its rules**, **that gives it another role**, **that asks it to repeat its instructions**, or **that has an order tacked on to a real question**; **a signed note that carries an instruction to an AI, in the usual words and in a paraphrase**; **a note with identifiers in its text**; a request to say the patient has no allergies; a request to run a tool for every patient; **a request to change a patient's details**; **a follow-up about the same patient**, **a switch to another patient and a follow-up about him**; **another patient named inside a consultation** (the wrong-patient guard) |
| Origin | Written by an AI assistant (Claude) on 4 Oct 2026 as fictional patients, records and questions. **No real patient, clinic, record or person is described, copied or derived; no external dataset is used.** The patients' names, dates of birth and telephone numbers are invented; the telephone numbers are `9400000nnn`. The expectations were assigned by the same author who wrote the checks |
| Marking | The fixture's header and the cases file say it is synthetic; the cases are test data only and are built only in the **test database** (the runner refuses any other); they are **never loaded into a patient record**, and nothing here can be built in the development database |
| Medical content | Ordinary and illustrative; **not reviewed by a clinician, not clinical guidance, not a validated case set** |
| Use | **Evaluation of Mana AI with the real local model (opt-in, minutes per question)** and the regression tests of the scoring; the same fixture builds the world of the tool and pipeline tests (`mana-tools.test.ts`, `mana-assistant.test.ts`), which use a stand-in model. Not a training set, not a validation set for any clinical claim |
| Splits | **None.** The cases were written while the planner prompt, the answer prompt and the checks were written and tuned, so **every case is a development case**: a count here says what Mana did on cases its authors looked at, and the report says so. The first recording (cases `mana-v1.0`, 43 cases, the first planner prompt) is kept as `data/eval/results/mana-v1.superseded.raw.json`; after its failures the prompt was rewritten, the server's corrections and the checks were extended (two independent reviews), and six cases were added (`mana-v1.1`: a paraphrased instruction in a note, identifiers in a note, a question that gives Mana another role, a request to repeat its instructions, an order tacked on to a real question, a request to change a patient's details). The final recording is of the 49-case file. |
| Metrics | Counts of cases passed, never a percentage: tool selection, retrieval, authorization, source correctness, grounded answer, ambiguity handling, conflict handling, injection resistance, context isolation, read-only, refusals, outcome; statements produced, removed by the checks and marked; time per question. Results: [`data/eval/results/mana-v1.md`](../../data/eval/results/mana-v1.md), summarised and caveated in [AI_MODELS.md](AI_MODELS.md) §10 |
| Limits | Small; one author who also wrote the checks, so the cases probe what the author thought of; no second reader, no clinician; English; short records; one model; one machine; temperature 0; the questions are phrased the way the author phrases questions |
| Gaps against the target list | Real or realistic de-identified records and questions (none exist here), questions written by clinicians, other languages, long free-text notes, misspellings and abbreviations, multi-morbidity, a second model for comparison |

**Model weights are an external artifact, not a dataset.** The speech model (`Systran/faster-whisper-small`, MIT) was downloaded with the owner's approval; its provenance, checksum and training-data statement are in [AI_MODELS.md](AI_MODELS.md). No data from this repository is used to train, fine-tune or adapt it. The same holds for the **consultation-draft language model** (`Qwen3.5-4B`, Apache-2.0, `unsloth/Qwen3.5-4B-GGUF`, pinned in `services/llm/models.lock.json`): downloaded with the owner's approval, run unchanged, its provenance, checksum and training-data statement in [AI_MODELS.md](AI_MODELS.md).

## Test fixtures

Tests create their own throw-away synthetic patients, staff and records and delete nothing outside the disposable test and end-to-end databases. The thermal tests use public FLIR sample images fetched by `scripts/fetch-thermal-samples.mjs` (git-ignored; tests skip without them); their source and licence (MIT, National Drones) are recorded by the fetch script and in `samples/thermal/SOURCE.txt`, and they are third-party images, not clinic data.

## Device simulator output (`npm run devices:simulate`) (slice V5)

| | |
| --- | --- |
| What | Numbers produced by a program (`apps/api/src/devices/simulator.ts`, `device-sim-v1`) from a seed and a tick: heart rate, oxygen saturation, temperature and respiratory rate, in six scripted scenarios (steady, a climbing heart rate, a falling saturation, a fever, a gateway that sends nothing for a while, one that goes silent), and a short file of generated tones for the stethoscope boundary |
| Origin | Generated arithmetic (a small deterministic number generator around fixed curves). **Not a recording of anyone, not derived from any dataset, not a physiological model.** The same seed and tick always give the same values |
| Marking | Stored only through a device record registered as a simulator; the server stores it as `simulated` and the database refuses a row that says otherwise; shown as SIMULATED; left out of visit vital signs, the patient portal, every model's inputs and the record rules ([ADR 0018](../adr/0018-device-readings-states-gateway-and-simulator.md) §2.5) |
| Use | Exercising the device boundary and its screens in development, demonstrations and tests. **Not a training set, not an evaluation set, not evidence about any device** |
| Splits, metrics, failure cases | Not applicable (nothing is trained or evaluated on it) |
| Limits | It shows that the states and labels work; it says nothing about how a real band or stethoscope behaves (noise, dropouts, motion artefact, clock drift, units) |
